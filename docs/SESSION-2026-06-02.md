## 1. What Assisty is
A multi-tenant, **AI-native customer-service & commerce platform**. A business connects channels (WhatsApp, website widget, later Instagram), gives the agent knowledge + a persona, and the AI answers customers, **suggests products**, **places & tracks orders**, and lets an operator manage everything from a console. Backend is a **NestJS monolith**; data is **Supabase Postgres (+pgvector)**; AI is **Google Gemini**.

## 2. Stack (current)
- **Backend:** NestJS 11 (monolith) · postgres.js · pg-boss (Postgres queue) · pino logs · zod config.
- **DB:** Supabase Postgres (session pooler, SSL) + pgvector(1536).
- **AI:** Google Gemini via its **OpenAI-compatible** endpoint (`/v1beta/openai`). Chat = `gemini-2.5-flash` (fallback `gemini-2.5-flash-lite`); embeddings = `gemini-embedding-001` with `dimensions:1536`.
- **Channels:** website widget (live) + WhatsApp webhook (built, dry-run) ; Instagram pending.
- **Dev:** runs natively (`npm run start:dev`) — Docker blocked on this machine (WSL corruption), so we went Docker-free.

## 3. Architecture — three layers + suggestions (the key principle)
```
1. AI CONVERSATION LAYER  — channels, tone/persona, RAG retrieval, suggestion engine,
                            and the COMMERCE BRIDGE that fetches operational data
2. KNOWLEDGE BASE LAYER   — RAG/pgvector: profile, FAQ, policies, free text, website import
3. BUSINESS OPERATIONS    — RELATIONAL tables: catalog, orders, settings (+ later CRM,
                            invoices, payments, shipments, inbox, analytics)
```
**Golden rule:** operational data (orders, tracking, prices, stock) lives in **relational tables and is FETCHED**, never embedded in RAG and never invented. Fuzzy prose (profile, FAQ, policies) lives in RAG. The conversation layer **bridges** to operations by fetching real rows and feeding them to the model as authoritative context.

## 4. What was built TODAY

### 4.1 Gemini integration (replaced OpenRouter)
- AiService points the OpenAI SDK at Gemini's OpenAI-compatible endpoint.
- Chat `gemini-2.5-flash`; on transient 429 it **falls back to `gemini-2.5-flash-lite`** (separate quota).
- Embeddings `gemini-embedding-001` pinned to **1536 dims** to match the pgvector column (no migration).
- The OpenRouter-only `models[]` param is gated off for Gemini.

### 4.2 RAG engine + Knowledge Base module
- `RagService.retrieve` (embed query → cosine search pgvector, tenant-scoped) + `buildContextBlock`; degrades gracefully if embeddings fail.
- `KbService` collectors → chunk → embed → `kb_chunks`: **Business Profile, FAQ, Policies, Free text, Website import** (HTML → text). Endpoints `POST /kb/{profile,faq,policies,text,website}`, `GET /kb/sources`, `DELETE /kb/:type`.
- **Master Prompt / Persona** (`kb_documents` type `agent-instructions`, NOT embedded) + **5 tone templates** (Professional/Friendly/Playful/Concise/Empathetic) — `POST/GET /kb/agent`.
- **Conversational tone redesign:** greet once, use contractions, no canned closers, speak as "we", concise, vary wording (anti-robotic prompt).

### 4.3 Website widget (embeddable)
- `GET /widget.js` — a floating chat bubble that any site can embed (`<script src=".../widget.js" async>`), calls `/web/chat`; CORS enabled.
- `GET /widget-demo` — a demo "customer website" with the widget embedded.

### 4.4 Business Operations Layer (relational) — `backend/src/operations/`
- **Catalog** (`products`): name, category, description, price, currency, stock, options{sizes,colours}. CRUD `/catalog/products`.
- **Orders** (`orders`): order_number (sequence), customer_ref/name, status, payment_status, tracking_number, carrier, shipping_address, items(jsonb), subtotal, total, currency. `GET /orders`, `GET /orders/:id`, `POST /orders`, `PATCH /orders/:id/{status,payment,ship,cancel}`.
- **Settings** (`tenant_settings`): cancellation policy (`cancellableStatuses`), `autoConfirmOrders`, `allowCustomerCancel`, currency. `GET/PUT /settings`.
- **Cancellation is policy-gated**: cancelling an order whose status isn't in `cancellableStatuses` is rejected (400).
- Migration `0002_operations.sql`.

### 4.5 Suggestion engine + Commerce bridge (`web/commerce.service.ts`)
- On each chat turn:
  - **Order/tracking intent** (order number or "track/where is my order") → fetch the **real order row** → inject as authoritative "LIVE ORDER DATA" (relational, not RAG).
  - **Product interest** → search the catalog → return structured `suggestions { products, quickReplies, attributePrompts }` + inject real product names/prices into context.
- Chat response is `{ reply, suggestions, ... }`.

### 4.6 Operator Console (`/test`) — web UI
Tabs: **Chat · Knowledge · Catalog · Orders · Settings**.
- **Chat:** renders product cards with **size/colour selects + 🛒 Order button** → `POST /orders` (places a real order); shows model + ctx hits.
- **Catalog:** add/list/delete products.
- **Orders:** records table (items, prices, status, payment, tracking) + controls (status dropdown, add tracking → Ship, Cancel).
- **Settings:** toggle cancellation policy, auto-confirm, currency.
- **Knowledge:** persona/tones + KB collectors + sources.

## 5. Data model (Supabase Postgres)
| Table | Purpose |
|---|---|
| `tenants`, `users` | tenancy (single playground tenant in dev) |
| `channel_connections` | per-channel connection (whatsapp/web/...) |
| `conversations`, `messages` | chat history (inbound/outbound) |
| `kb_documents`, `kb_chunks` (vector 1536) | RAG knowledge + persona |
| `usage_ledger`, `webhook_events` | metering + webhook idempotency |
| `products` | structured catalog (price/stock/options) |
| `orders` | relational orders (status/payment/tracking/items) |
| `tenant_settings` | cancellation policy + order defaults |

## 6. Key API endpoints
- Chat: `POST /web/chat {sessionId,text}` → `{reply, suggestions, model, contextHits}` · `GET /web/messages`
- KB: `POST /kb/{profile,faq,policies,text,website,agent}` · `GET /kb/{sources,agent}` · `DELETE /kb/:type`
- Catalog: `GET/POST /catalog/products` · `PUT/DELETE /catalog/products/:id`
- Orders: `GET /orders` · `GET /orders/:id` · `POST /orders` · `PATCH /orders/:id/{status,payment,ship,cancel}`
- Settings: `GET/PUT /settings`
- Widget: `GET /widget.js` · `GET /widget-demo`
- Health: `GET /health` · `GET /health/db`

## 7. Verified working (today)
- Chat answers from KB (RAG) with the chosen tone; greets naturally; grounded.
- "do you have running shoes?" → product card + size/colour + Order button.
- 🛒 Order → real order created (#1001–#1003), shows in Orders tab.
- "where is order 1001?" → real status + tracking (relational, e.g. TRK999).
- Ship adds tracking; **Cancel respects the Settings policy** (shipped → blocked, pending → allowed).
- Embeddings (Gemini 1536) ingest + retrieve confirmed.

## 8. Known limitations / pending
- **Auth/multi-tenant**: dev uses a single resolved tenant; no operator login yet (planned with the Flutter app + Supabase Auth).
- **WhatsApp/Instagram live**: WhatsApp webhook is built (dry-run); going live needs Meta credentials (App Secret, Phone Number ID, Access Token) + a public tunnel (ngrok). Instagram needs a channel adapter + Meta review.
- **Order placement via pure chat text** (no button) would need LLM tool/function-calling — currently placing uses the suggestion's Order button.
- **Free Gemini tier** rate-limits under rapid use → occasional fallback reply (mitigated by the lite-model fallback).
- Not yet built: CRM, invoices, payments, shipments module, analytics, event bus, Flutter app.
- Everything is **local + uncommitted** beyond the last git commit; secrets live only in gitignored `backend/.env`.
